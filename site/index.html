Free and open source, for Windows, macOS and Linux.

Built on VS Code. Your setup comes with you.

{{name}} is a fork of VS Code (Code - OSS, the open-source core of VS Code), not a plugin and not a new editor to learn. The editor you know is all there; {{name}} adds to it.

  1. Your extensions

    Install them from Open VSX, the open extension registry that VS Code forks use. Most of the VS Code extensions you run are published there.

  2. Your themes, keybindings and settings

    The same commands, the same shortcuts and the same settings.json. Vim, Emacs and other keymaps are extensions, like in VS Code.

  3. Your profile

    In VS Code, run Profiles: Export Profile… to save your settings, keybindings, snippets and extension list to a file. In {{name}}, choose Import Profile… in Preferences: Open Profiles (UI).

What {{name}} adds to VS Code.

A canvas that draws how your code runs, card by card, from the request to the table it writes. Here it is, live, on the demo shop.

The real canvas, on a small demo shop. Drag to move around; hold Ctrl and scroll to zoom. It opens full screen. More to try.

Your agent changed 2 files. Which endpoints did it reach?

Ask the agent to show what it did, or run Show Git Changes in Flow. One canvas holds the whole change: every endpoint the changed code reaches, cut down to the changed methods, added lines in green and removed lines in red.

Keep or undo each change where you see it. After every prompt, the Agents dock lists the flows that turn touched.

Review the change in the demo

A request leaves your service. Where does it go next?

Pick an endpoint and follow the chain it runs, card by card, to the table it writes. An HTTP call continues into the route it reaches, a message into the listener of its topic or queue, across languages.

Links found by matching a name or a path are drawn dashed, as guesses, so you always know what is certain.

Follow an invoice across two services

Three agents are running. Which one is waiting for you?

Claude Code, Codex and any CLI run as their real tools, in terminals. The Agents dock ranks what needs you first: an approval with its text, a question, an error, a finished turn you have not read.

Each row shows the model, how full its context window is, and what it costs. Start an agent in its own git worktree and get warned when two agents edit the same file.

Answer a waiting agent

Your agent reads a dozen files before you type. Is any of them wrong?

CLAUDE.md and AGENTS.md, rules, skills, subagents, hooks, MCP servers and permissions, on one map, with a health score and what each piece costs in tokens before you type.

Rules whose paths match nothing, broken frontmatter and hooks that never fire are found without an LLM. Permissions you keep granting become proposed rules, applied only when you say so.

Works with the agents you already use.

Claude Code

Runs in its own terminal, as it does today. Its approvals, questions and context window show up in the dock.

Codex

The same, side by side with Claude Code on the same project, each in its own worktree if you like.

Any CLI

Add the command you run, and it gets a row in the dock and a place on the status island.

Your agent can use the canvas too

{{name}}'s MCP server gives the agent tools to find entry points, read a flow as text and walk you through it as a tour. Ask "how does an order get placed?" and the answer plays on the canvas.

The agent tools

you    how does an order get placed?
agent  find_entry_points  9 endpoints
       flow_text "POST /orders"  12 cards, 3 services
       tour  8 steps, playing on the canvas
